# Frank Gemini V1.2 开发实现审查报告

## 审查范围

- 审查提交：`3667c5b feat: implement Frank Gemini Agent V1.2`
- 审查目标：确认 V1.2 是否满足 PRD 中“场景一：个股买入决策与观察计划”“场景二：板块观察池与教学复盘”的核心要求。
- 测试结果：本地执行 `tests/run_tests.py`，共 24 个用例通过。
- 额外验证：对常见自然语言入口做了路由冒烟测试；对板块数据采集做了真实 AkShare 调用验证。

## 总体结论

当前实现已经搭出 V1.2 的基础骨架，包括新意图路由、场景一、场景二、Observation Memory、术语队列和公共输出层。但核心用户路径仍存在阻断问题，不建议直接作为 V1.2 部署。

建议先修复以下 P1 问题，再进入部署验证。

## P1：常用个股分析入口没有稳定进入场景一

### 位置

- `src/listener/intent_router.py:54`
- `src/listener/feishu_listener.py:185`
- `src/listener/feishu_listener.py:680`

### 触发条件

用户输入常见问法，例如：

- `上海电力最近一直跌，可以买吗`
- `分析 上海电力`

### 当前表现

- `上海电力最近一直跌，可以买吗` 会被路由为 `chat_fallback`。
- `分析 上海电力` 会落回旧的 `process_instant_analysis` 流程。

### 影响

用户会绕过 V1.2 场景一，仍可能看到旧版“新闻依赖 + 买入/止损/止盈参考位”的输出。这会直接破坏新版定位：先翻译问题、结论先行、数据依据、条件计划、术语解释。

### 建议修复

- 扩展 `route_intent` 的场景一关键词和句式识别，例如 `可以买吗`、`能买了吗`、`最近一直跌`、`分析 + 股票名`。
- 对无法明确归类但包含股票名或股票代码的“分析类问题”，优先进入 `SCENARIO_STOCK_DECISION`，不要落回旧流程。
- 增加测试用例：
  - `route_intent("上海电力最近一直跌，可以买吗") == SCENARIO_STOCK_DECISION`
  - `route_intent("分析 上海电力") == SCENARIO_STOCK_DECISION`
  - `route_intent("分析下上海电力的走势情况，是否有合适的买入点") == SCENARIO_STOCK_DECISION`

## P1：观察池复盘入口未真正实现复盘

### 位置

- `src/listener/feishu_listener.py:358`
- `src/memory/observation_memory.py`

### 触发条件

用户输入：

- `复盘观察池`
- `复盘观察池 1`

### 当前表现

路由能识别该意图，但处理函数只是列出最近观察池记录，没有根据后续 K 线判断观察条件是否成立，也没有写入 `observation_reviews`。

### 影响

这会导致场景二缺少最关键的“教学复盘”闭环。Frank 不能解释“为什么当时只是观察”“为什么后续没有买点”“哪些条件成立或失效”，也无法沉淀给下次使用。

### 建议修复

- `复盘观察池`：展示最近可复盘的 observation runs。
- `复盘观察池 1`：按 run id 或序号进入具体复盘。
- 拉取候选股后续 K 线，判断观察条件是否成立，例如是否“一日游”、是否“有效跌破”、是否“放量修复”。
- 将复盘结论写入 `observation_reviews`。
- 输出应强调“复盘用于学习，不证明当初推荐一定正确”。

## P1：板块数据不可用时生成了假的观察方向

### 位置

- `src/listener/feishu_listener.py:316`
- `src/scraper/akshare_client.py:204`

### 触发条件

AkShare 东方财富板块接口失败或返回空结果。

### 当前表现

当 `collect_board_observation_inputs` 返回空列表时，代码会构造一个名为 `数据待确认方向` 的板块，并继续写入观察池。

### 实际验证

真实调用 AkShare 板块采集时，本地返回 `COUNT 0`，日志显示东方财富接口连接失败。该情况下当前代码会产生空壳观察池。

### 影响

Observation Memory 会被不可用数据污染。用户可能误以为 Frank 已经完成了板块筛选，但实际上没有可靠市场依据。这与 V1.2 的“不编造、不强推、数据缺失明确说明”原则冲突。

### 建议修复

- 数据为空时不要创建假的板块观察池。
- 返回“板块数据暂不可用”的降级回复，并标注数据源、失败原因和建议重试时点。
- 如需记录，可记录为失败运行状态，例如 `status=failed`，但不要作为有效 observation run 展示。
- 增加测试：当板块数据为空时，不写入 `observation_boards` 和 `observation_stocks`。

## P2：飞书帮助文案仍是旧产品说明

### 位置

- `src/listener/feishu_listener.py:371`

### 当前表现

`send_help` 仍包含以下旧定位表达：

- 每日 3 次定时资讯抓取
- 加仓
- 高频风险盯盘
- 给出加减仓建议

### 影响

用户在飞书里看到的帮助文案会和 V1.2 PRD、用户手册不一致。尤其“定时资讯抓取”和“加减仓建议”已经被标记为 Legacy 或降级功能，容易造成使用预期混乱。

### 建议修复

- 将帮助文案改成 V1.2 的 5 个主入口：
  - 个股能不能买
  - 收盘后看方向 / 板块观察池
  - 查看观察池
  - 复盘观察池
  - 记录术语 / 导出术语记录
- 对 Legacy watchlist / positions 标注为“历史功能，暂保留”。
- 不再宣传“每日 3 次资讯推送”和“AI 加减仓建议”。

## P2：旧流程仍可能输出强交易措辞

### 位置

- `src/listener/feishu_listener.py:680`
- `src/strategist/trade_advisor.py`

### 当前表现

旧的 `process_instant_analysis` 和部分 `TradeAdvisor` 输出仍包含较强交易表达，例如买入、止损、止盈、加仓等旧式口径。

### 影响

如果入口路由没有完全收敛到 V1.2，新用户仍可能看到与 PRD 合规口径冲突的表达。

### 建议修复

- 优先修复入口，避免常见问题进入旧流程。
- 对仍需保留的 Legacy 输出统一降级为：
  - 可观察
  - 等待确认
  - 可小仓位试错
  - 回避
  - 风险位 / 失效位
- 避免“最佳”“严禁”“建议建仓”“建议加仓”等确定性表达。

## 建议补充的验收测试

1. 场景一路由测试：
   - `上海电力最近一直跌，可以买吗`
   - `分析 上海电力`
   - `分析下上海电力的走势情况，是否有合适的买入点`

2. 场景二数据降级测试：
   - 板块数据为空时，不生成假的观察池。
   - 输出明确说明数据不可用和重试建议。

3. 观察池复盘测试：
   - `复盘观察池 1` 能读取指定 observation run。
   - 能写入 `observation_reviews`。
   - 输出包含条件是否成立、术语解释和下一次观察建议。

4. 帮助文案测试：
   - 飞书 `帮助` 输出不再包含“每日 3 次定时资讯抓取”“加减仓建议”等旧定位。

## 部署建议

当前版本建议暂缓部署为正式 V1.2。可以让开发侧先修复 P1 问题，再进行一次完整验收。P2 问题不一定阻断技术运行，但会影响产品定位和用户理解，也建议在同一轮修复。
