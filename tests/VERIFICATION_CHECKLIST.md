# Frank Gemini 功能验证红线清单 (Core Redlines)

为了确保系统的长期稳定性 (Rome wasn't built in a day)，任何代码变更必须通过以下红线测试：

## 1. 基础设施 (Infrastructure)
- [ ] **数据库无损升级**：新字段加入时，旧数据不丢失，查询不崩溃。
- [ ] **环境容错**：即使第三方库 (如 akshare/schedule) 缺失，自检脚本也要能运行 (Mock)。

## 2. 核心交互 (UX/UI)
- [ ] **视觉统一性**：所有核心推送必须使用 "飞书卡片 (Interactive Card)"，禁止直接发送 Markdown 源码。
- [ ] **帮助系统**：`帮助` / `help` 指令永远可用。

## 3. 业务逻辑 (Logic)
- [ ] **回归测试：池子**：`池子` 指令在有/无数据时均能正常展示，且显示股票名称。
- [ ] **模糊匹配**：监控指令必须支持中文名称识别。
- [ ] **状态流转**：`买入` 后股票必须从观察池正确移动到持仓池。
